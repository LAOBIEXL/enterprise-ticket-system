- 文档状态：当前有效

## 1. 项目目标

本项目用于建设一套面向约 500 名企业员工的内部工单管理系统，解决通过微信群、电话和私聊处理技术问题时出现的遗漏、重复处理、责任不清、过程不可追溯等问题。

V1.0 的目标是跑通以下核心闭环：

```text
员工提交工单
→ 技术主管分派
→ 技术人员处理
→ 员工确认结果
→ 工单关闭
```

## 3. 当前实现概况

当前后端已经具备以下技术基础：

- Spring Boot；
- MyBatis-Plus；
- MySQL；
- Redis；
- Sa-Token 登录与权限校验；
- Swagger/OpenAPI；
- 统一泛型响应 `Result<T>`；
- Controller、Service、Mapper 分层；
- DTO 与 Converter；
- 全局异常处理；
- Controller 日志切面；
- 用户基础 CRUD 和分页查询；
- 基于 `sys_user`、BCrypt 与数据库 RBAC 的正式账号密码认证；
- 工单创建、本人/待办/全部分页查询、详情查询和完整状态动作；
- 启用部门/工单分类查询，以及工单分类分页、新增、修改和启停管理。

部门、用户、角色、权限及工单目标表已经通过 Flyway V1~V3 落库。正式用户认证、数据库角色权限加载、工单查询与状态闭环已经实现；工单分类管理已实现，其他管理端基础数据接口仍待实现。

旧 `User` CRUD 仍属于学习原型能力，不作为 V1.0 正式接口契约；正式认证使用用户名、BCrypt 密码哈希、Sa-Token 请求头和 Redis 会话。

## 5. V1.0 范围

V1.0 包含：

- 用户、部门、角色和权限管理；
- 工单分类管理；
- 员工创建和查看自己的工单；
- 技术主管查看、分派和转派工单；
- 技术人员查看和处理分配给自己的工单；
- 技术人员记录处理过程并提交解决结果；
- 员工确认结果或退回重做；
- 完整的工单操作记录；
- 登录认证、RBAC 接口权限和数据范围权限；
- 并发状态校验和统一错误响应。

## 6. V1.0 非目标

V1.0 暂不包含：

- 附件上传；
- 站内信、邮件、短信或微信通知；
- SLA 和超时提醒；
- 高级统计报表；
- 多租户；
- 复杂审批流；
- 关闭后重新打开；
- 工单物理删除；
- 企业单点登录和外部组织架构同步。

## 7. 关键工程约束

- 业务逻辑放在 Service 层，Controller 只负责接收参数和返回结果；
- Entity 不直接承担所有接口输入输出，接口使用 DTO；
- Entity 与 DTO 的转换集中在 Converter；
- 状态变化必须经过状态机规则校验；
- 接口权限和数据权限必须同时校验；
- 状态更新和操作记录写入必须位于同一事务；
- 并发更新应使用原状态条件或版本号，冲突返回 HTTP 409；
- 工单处理记录只追加，不直接修改和物理删除；
- 数据库结构变化通过新增迁移版本完成，不修改已经执行的迁移文件；
- 文档中禁止记录真实密码、Token 或生产凭据。
